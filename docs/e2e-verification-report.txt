 本次修复/新增过程中的三个环境级坑（复现与规避）：
------------------------------------------------------------------------------
1) 沙箱后台进程会丢失 JAVA_TOOL_OPTIONS 环境变量（JVM 不打印 "Picked up"，
   java.io.tmpdir 回落 C:/Windows）→ Tomcat createTempDir 抛
   AccessDeniedException，服务无法启动。
   规避：把 -Djava.io.tmpdir=D:/1/zx-learn/logs/tmp 直接写在 java 命令行上。

2) 旧 fat jar 无法被 spring-boot:repackage 原地替换（构建日志显示 SUCCESS、
   "Replacing main artifact"，但磁盘文件内容/mtime 不变，嵌套依赖仍是旧版）。
   规避：重新打包前先 rm target/<module>.jar（及 .original），删除后重建即生效。

3) 构建产物 freshness 校验：不要只看 jar 外层 mtime，
   用 python zipfile 检查 BOOT-INF/lib/zx-common-*.jar 内是否含
   jackson/SafeLongSerializer.class 才可靠。
